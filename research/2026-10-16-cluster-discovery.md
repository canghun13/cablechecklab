## Evidence and competition method

- Use direct Google/Naver pages when accessible, general web discovery, Reddit, specialist forums/Stack Exchange, manufacturer support and video sites. Record access failures rather than imply a source was checked successfully.
- Distinguish visible views/votes/comments from search volume. Repeat threads across independent venues are a demand clue, not a numeric market-size estimate.
- Separate generic head-term competition from exact long-tail results and actual free interactive rivals. A documentation-heavy result set is not automatically a Tool gap.
- Reopen prior HOLD/GO candidates only when new evidence or a materially different independent workflow changes the old reason. Never relabel an old candidate as new.
- Launch only a coherent user journey with genuinely distinct useful Tools, public technical bases, static maintenance, explicit unknowns and no hardware-detection fiction. Prefer one strong cluster over filler expansion.
